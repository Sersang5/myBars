# MyBars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA personal para registrar/valorar bares por ciudad ("Mis Bares" + "Pendientes") y descubrir nuevos con un explorador IA (Claude + Google Places).

**Architecture:** Next.js App Router monolito. La lógica vive en `lib/` como módulos puros con dependencias inyectadas (repositorio, cliente Places, cliente LLM) y se testea con Vitest sin red; `app/` solo compone UI y rutas API. Datos en Supabase (Postgres + RLS + magic link); listas de una ciudad se cargan completas y se filtran/ordenan en memoria.

**Tech Stack:** Next.js 15 (App Router, TypeScript strict), Tailwind CSS 4, `@supabase/supabase-js` + `@supabase/ssr`, `@anthropic-ai/sdk` + `zod`, Vitest, Playwright, Supabase CLI (local, requiere Docker Desktop).

**Spec:** `docs/superpowers/specs/2026-10-17-mybars-design.md`

## Global Constraints

- Idioma de la UI: español. Código, identificadores y commits: inglés.
- Puntuaciones: `1–5` en pasos de `0.5`; nota global = `rating_overall_manual` ?? media de `rating_local/service/food` no nulos, redondeada a 0.1; `null` si no hay ninguna.
- Precio: entero `1–4`, mostrado como `€`, `€€`, `€€€`, `€€€€`.
- Claves (`GOOGLE_MAPS_API_KEY`, `ANTHROPIC_API_KEY`) solo en código de servidor (`import "server-only"`); nunca con prefijo `NEXT_PUBLIC_`.
- Modelo: `process.env.ANTHROPIC_MODEL ?? "claude-opus-5-5"`, `output_config.effort: "low"`, `betas: ["server-side-fallback-2026-07-01"]`, `fallbacks: "default"`. Sin `thinking: disabled`, sin `budget_tokens`, sin `tool_choice` forzado, sin prefill.
- Places API (New) con cabecera `X-Goog-FieldMask` explícita en cada llamada y `languageCode: "es"`.
- Caché de detalles de Places: 7 días (`details_fetched_at`).
- Explorador: hasta 3 consultas, ~40 candidatos, detalles de los 12 primeros, devuelve 5–8.
- Un solo usuario: `ALLOWED_EMAIL` en env; registros nuevos desactivados en Supabase.
- Móvil primero: diseño probado a 375 px de ancho.

## Review Focus

1. **Local sin `locality`** (bares en Oleiros, Arteixo, Culleredo...): Google a veces no devuelve `locality`; se espera caer a `postal_town` → `administrative_area_level_2` y nunca fallar el alta. Test en Task 3.
2. **Tags casi duplicados** ("Tortilla ", "tortilla", "TORTILLA"): se esperan como un único tag; acentos se conservan ("tortílla" ≠ "tortilla" es aceptable, pero espacios y mayúsculas no). Test en Task 5.
3. **Bar sin ninguna puntuación**: nota global `null`, se ordena al final en cualquier orden por nota, y la tarjeta muestra "Sin valorar". Test en Task 5.
4. **Claude devuelve un `placeId` que no estaba entre los candidatos** (alucinación) o repetido: se descarta sin romper la respuesta. Test en Task 11.
5. **Añadir dos veces el mismo local** de Google: no se duplica; se devuelve el existente (y si estaba en pendientes, se mantiene su estado hasta que el usuario lo valore). Test en Task 6.
